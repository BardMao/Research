# 原程序工作原理与重写设计

分析对象：[hjhhoni/pkulaw 的北大法典爬虫GUI.py](https://github.com/hjhhoni/pkulaw/blob/main/北大法典爬虫GUI.py)，读取时文件 blob SHA：`895990fcd5863e00a6ace850fe9149aedd5dd01f`。原仓库为 MIT 许可。本目录实现独立编写，不包含原程序副本。

## 原流程

1. PyQt5 提供目录、等待时间、采集、下载、停止按钮。QThread 执行任务，通过信号更新日志和进度。
2. DrissionPage 连接 `127.0.0.1:9333`，取最新标签，从第一个 tbody 的 tr 中各取第一个 a 的 href。
3. urls.txt 作为待下载集合，采集时去重追加。
4. 下载时创建 ChromiumPage，每条 URL 随机等待 1–10 秒，导航后固定等待 2 秒，读取 `.fulltext`。
5. 正文第一个空白分词作为标题，清理部分文件名字符，写成 TXT；成功后从 urls.txt 删除。
6. 每批最多 10000 条；部分网络错误触发中断，最后退出下载浏览器。

## 具体缺陷

| 原设计 | 后果 | 新实现 |
| --- | --- | --- |
| 下载另建 ChromiumPage | 未明确复用已登录上下文 | 同一上下文新建详情标签 |
| set 保存待办并反复重写文本 | 顺序丢失，异常写入可丢队列，成功历史消失 | SQLite 事务与任务状态 |
| 成功 URL 从队列删除 | 再次采集时可重新加入已完成 URL | URL 主键及 done 状态 |
| 第一个词作文件名 | 标题截断，同名覆盖 | h1/页面标题回退与 URL 哈希 |
| 固定 sleep 后读正文 | 页面慢时失败或取不到正文 | 显式等待正文元素 |
| 内层捕获错误后返回 | 外层线程可能仍宣告成功 | 任务中止与逐条失败日志分离 |
| 状态变量配合 sleep | 停止延迟，采集循环不检查停止 | Event 检查与可中断等待 |
| 仅当前页、固定选择器 | 页面结构变化时难适配 | 可配置 CSS、有限翻页 |
| 主线程初始化浏览器 | 连接阶段可能卡住界面 | 浏览器操作全部放到工作线程 |

## 新实现的数据一致性

`pending → done / failed`。每次实际处理结果累加 attempts；中间可重试失败保持 pending，最终失败才变为 failed。登录或权限中止不消耗当前任务。用户可把 failed 批量重新排队。

文件先写临时文件再替换，两个文件完成后再提交 done。文件系统和 SQLite 之间没有跨系统事务：极端中断可能留下 TXT 或临时文件，但未标 done 的任务仍可重跑；成功记录不自动核验被用户删除的文件。

分页用链接集合变化确认新页，以重复集合和最大页数防止循环。这个通用策略不假设未观察过的站点接口；真实页面需确认 CSS 和内容完整性。
